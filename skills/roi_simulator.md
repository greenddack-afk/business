# ROI 시뮬레이터 절차 (roi_simulator v1)

Finance 에이전트 프롬프트에 원문 그대로 삽입된다. **LLM은 입력 숫자만 정하고, 손익분기·시나리오 산수는 코드(`finance.py`)가 다시 계산해 덮어쓴다.** 산술 실수가 리포트에 남지 않게 하기 위한 구조다.

단위: 초기투자·월 고정비·누적손익은 **만원**, 단가·원가·변동비·기여이익은 **원**, 판매량은 **개(건)**.

## 1. 파라미터 선택
1. `data/industry_params.json`에서 Normalizer가 준 `industry_code`의 표를 고른다.
2. `manufacturing`이면 `interpretation`(`oem_import` 기본 / `own_manufacturing`)에 맞는 투자 항목 표를 쓴다. 판단이 애매하면 **자본이 적게 드는 해석(oem_import)** 을 기본으로 하고, 다른 해석의 총투자 차이를 `summary`에 한 줄 병기한다.
3. **항목 구조(어떤 행이 있는지)는 바꾸지 않는다.** 표의 `low / base / high` 중 검색 근거에 가장 가까운 값을 고르거나, 근거가 있으면 그 값으로 대체한다. 항목을 추가하거나 삭제하지 않는다.

## 2. 숫자 채우기
- 검색 결과에 해당 수치가 있으면 `confidence="sourced"`, 그 결과의 URL을 `source_url`에 넣는다.
- 없으면 업종 파라미터의 `base` 값을 쓰고 `source_url=""`, `confidence="estimated"`로 둔다.
- 판매 단가는 검색으로 확인된 경쟁 제품 가격대에서 잡는다. 확인되지 않으면 추정치로 표기한다.
- 가정은 조용히 넣지 않는다. 판매 단가, 원가율, 채널, 초기자본 규모는 모두 `summary`에 언급한다.

## 3. 계산 규칙 (코드가 재계산)
```
변동비(개당)      = 채널수수료 + 배송비 + 광고비 + 반품손실   (원)
                    채널수수료·광고비·반품손실 = 판매가 × 각 비율
개당 기여이익      = 판매가 − 개당 원가 − 변동비
월 손익분기 판매량  = ceil( 월 고정비(원) ÷ 개당 기여이익 )
                    개당 기여이익 ≤ 0 이면 손익분기 없음 → value=0, note에 "도달 불가" 기재
초기투자 회수 개월  = 기본 시나리오 월 판매량이 정상 궤도일 때, 총 초기투자 ÷ 월 순이익
```

## 4. 12개월 3시나리오
- LLM이 정하는 것은 기본 시나리오의 **정상 궤도 월 판매량**(steady-state) 하나뿐이다. 근거(경쟁 제품 리뷰 수, 검색량, 유사 사례 등)를 `note`에 쓴다.
- 보수 / 낙관은 `industry_params.json`의 `scenario_model.volume_multiplier`(보수 0.5배, 낙관 1.8배)를 코드가 곱한다.
- 월별 판매량 = 정상 궤도 월 판매량 × `ramp[m]` (`ramp`는 1~12개월 램프업 계수, 파라미터 파일에 고정).
- **12개월 누적 손익(만원) = Σ(월 판매량 × 개당 기여이익) − 월 고정비 × 12 − 총 초기투자** (초기투자 포함, 세전).
- 음수(손실)는 그대로 표기한다. 낙관적으로 반올림하지 않는다.

## 5. 수익성 점수
`viability_rubric.md`의 profitability 앵커를 인용해 점수를 **먼저** 확정한다. 기여이익률 = 개당 기여이익 ÷ 판매가, BEP 비율 = 월 손익분기 판매량 ÷ 기본 시나리오 월 판매량이다.

## 6. 출력 체크리스트
- [ ] 모든 숫자가 `{value, unit, source_url, confidence}` 형태인가
- [ ] `source_url`이 비면 `confidence`가 `estimated`인가
- [ ] 초기투자 항목이 업종 표의 항목과 일치하는가
- [ ] `summary`가 결론 문장(예: "손익분기는 월 N개이며 …")으로 시작하는가
- [ ] 점수 → 설명 순서를 지켰는가
